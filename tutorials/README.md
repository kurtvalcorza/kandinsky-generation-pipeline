## Two things this tutorial does that most of the fleet's others do not

**It encodes every prompt once through the prior pipeline and drops the prior before anything is trained.** The prior pipeline (prior model + CLIP ViT-G text and image encoders) takes ~7 GB in float16 and is released before training so the UNet training graph has full VRAM headroom. Section 5 encodes the 60 captions, the generation prompts and the empty negative prompt, writes the image embeddings to a safetensors cache in the run directory, and releases the prior; every later stage process — including the fresh reload of Section 9 — reads the same cached embeddings instead of loading the prior again.

**It scores a generator without pretending a number is quality.** Generation has no ground truth, so the notebook reads three kinds of number and names each: the held-out *denoising loss* (the training objective on photographs the model never trained on, with identical noise for the frozen and the adapted model; the only assertion is the guaranteed one, that the kept epoch's validation loss is no higher than the frozen model's, and the test loss is printed, not asserted), CLIP scores of generated images (prompt alignment, which species CLIP thinks it sees, closeness to the held-out photographs), and the same CLIP scores on the real photographs — the *real-photo reference line*, computed leave-one-out (each photo's reference similarity excludes the photo itself), which is a reference, not a ceiling: generated images can score above it. None of them is a human judgement.

## Conformance notes

- **Standalone carrier (ST1–ST8, SRC4, SRC12):** the primary path performs no clone, repository install, or repository import in the kernel. Section 2's carrier cell holds `CARRIED_FILES` — the package's four modules at their repository paths under `src/`, the stage runner, the lock as `requirements.txt`, the three snapshot manifests, the licence and a generated `source.json` (repository, revision, per-file SHA-256) — writes each into a fresh run directory and verifies it against `CARRIED_HASHES`, stopping on a mismatch. The carried text is the repository's, byte for byte (UTF-8, LF newlines), with no rewrites; the `weights` stage asserts each carried manifest against the package's pinned identity before staging.
- **Isolated environment (RUN1, RUN10, ENV1, ENV2, ENV6; §25.13):** no cell pip-installs into the kernel, and kernel cells import only the standard library, `IPython.display` and (for the BYOD upload) `google.colab`. The install cell downloads the `uv` 0.12.15 manylinux wheel by URL and refuses it unless its size and SHA-256 match, creates a managed CPython 3.12.12 virtual environment, and installs the carried lock with `uv pip install --require-hashes --only-binary :all:`. It removes Hugging Face tokens and the kernel's `PYTHONPATH` from the stage environment, sets `MPLBACKEND=Agg`, prints the environment's Python, `torch`, `diffusers`, `transformers` and `peft` versions and stops if CUDA is not visible there. `run_stage` runs one stage per process, streams its output to the cell and to `logs/<stage>.log`, and on failure raises a `RuntimeError` carrying the stage's own exception type and message.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried file, its hash, the carried lock or the manifests differ from the repository, when the lock does not pin every `pyproject.toml` pin or carries an unhashed entry, or when the notebook is not byte-identical to the generator's output. `tests/test_tutorial_stages.py` executes the generated carrier and `run_stage` code, and runs every stage on CPU against stubs (pre-flight only).
- **Model acquisition (MOD1–MOD9):** `stage_missing_files`, `stage_missing_prior_files` and `stage_missing_scorer_files` fetch only the manifest entries that are absent, from the Hugging Face Hub at the immutable revisions (never `main`); `verify_snapshot`, `verify_prior_snapshot` and `verify_scorer_snapshot` re-hash every entry; `KandinskyPipeline.from_pretrained(weights_dir=..., prior_dir=..., use_lora=True)` loads the decoder UNet with an untrained LoRA attached, the MoVQ, and the scheduler config; the prior is loaded by `encode_prompts` and released by `release_prior`. Every file is safetensors or JSON/text; nothing is unpickled and no remote code runs.
- **Stages (§4.1), one process each:** `weights` (stage and verify the three snapshots) → `prepare`: `fetch_sample_dataset` / `load_byod_dataset` (sample acquisition), `dataset_manifest` + `validate_dataset` refusal probes (validation, with the size limits and a dataset digest), seeded stratified roles (36 / 12 / 12), recorded so every later stage rebuilds and re-checks the same records → `encode`: `pipe.encode_prompts` + `release_prior`, embeddings written to a safetensors cache → `frozen`: `pipe.evaluate` and `pipe.generate` + `score_generations` with `real_photo_reference` (baseline and the leave-one-out real-photo reference) → `adapt`: `pipe.adapt` (bounded LoRA fine-tuning), the trained in-memory model's test loss and a fixed-seed image recorded, `pipe.save_artifact` → `evaluate`: `KandinskyPipeline.from_artifact` in a fresh process, `pipe.evaluate` / `pipe.generate` on identical inputs (evaluation) → `reload`: `from_artifact` in a second fresh process with parity against the recorded in-memory values (export and reload, VER2/VER4), then `generate` on a new prompt (inference).
- **Score semantics (UNC1–UNC4):** CLIP cosine similarities and the argmax label rule are labelled as what they are; the denoising loss is the training objective, not a quality measure; no threshold is set and no calibration is claimed.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the frozen model is scored before adaptation on the same seeded latents, noise and timesteps, and the leave-one-out real-photo reference line is scored on the same photographs (a reference, not a ceiling); every metric is labelled sample-sanity evidence from 12 held-out photographs and 12 generated images with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** the split is seeded and stratified per species, no image appears in two splits (`check_split_disjoint`), validation selects the epoch and the test records are used for nothing but the final comparison; the notebook states that the captions are one template per species, that a random split assumes the photographs are independent (the sample takes one photograph per observer per species; BYOD users are told to remove near-duplicates — bursts, crops, the same individual or scene — because only exact copies are dropped), and that the public sample may overlap the generator's and the scorer's pretraining data (DAT9). In BYOD mode the split is stratified within each caption (not a group split), and the stated minimum is at least one caption with six or more distinct images.
- **Limits (VAL6):** the image-size range, the caption length, the token truncation and the record range are stated in the Prerequisites and printed from the schema before the model runs; three refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, the kernel resolves the zip (`BYOD_PATH`, or the Colab upload dialog only when `BYOD_PATH` is empty) and passes its path to the `prepare` stage, and the records flow through the same validation, encoding, baseline, adaptation, evaluation, generation, export and reload stages; an invalid zip stops the cell with a `RuntimeError` that repeats the validator's refusal. The expected zip layout, the image and caption contract and the privacy guidance — photographs of identifiable people and licensed material are restricted data — are stated in the Prerequisites and in Section 4, and a captions CSV is written to `outputs/` in that shape.
- **Guided layer (GDL1–GDL15, §3.5):** implemented in `tools/notebook_template.py` (`guided`, `setup` and stage cells) and rendered by `tools/build_notebook.py` /3.0. The opening carries observable **Learning objectives** (GDL5), **How to use this notebook** with the intended learner, prerequisites, *Run all*, form controls and the learner/infrastructure distinction (GDL1–GDL2), an **Input → Model/System → Output** table and a **Roadmap** with a fast path (GDL3–GDL4), and a collapsible **Glossary** (GDL6). Sections 5–8 and 10 state the question or a **Predict before running** prompt (GDL7); Sections 3–9 have **Expected result** / **What to notice** notes that describe normal output without fixed numbers (GDL8) and collapsible **Check your reasoning** answers (GDL9). Section 10 is an optional **Predict → Change one thing → Run → Observe → Explain** activity on the guidance scale, gated by `RUN_ACTIVITY = False` after the canonical path, with no download and no prior reload (GDL10). The runtime-check, carrier, isolated-install and staging cells are collapsed (`cellView: form`, `source_hidden`) under **Infrastructure** callouts and each carries `# @title Infrastructure: …` (GDL11); every numbered heading is tagged **[Concept]**, **[Evaluation practice]** or **[Engineering]** (GDL12). A **Troubleshooting** table covers the GPU, platform, disk, carrier-integrity, `uv` download, `uv venv` / `uv pip install` failures, failed stages, Hub download, digest mismatch, photograph fetch, out-of-memory and BYOD failures, and no row asks for a runtime restart (GDL13); **Conclude with evidence** gives a conclusion template and a transfer prompt (GDL14); learner prose says “notebook” throughout (GDL15). `tools/validate_release_assets.py` fails if any of these elements, the section tags, the infrastructure collapse or the activity gate is lost.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
