## Two things this tutorial does that most of the fleet's others do not

**It encodes every prompt once through the prior pipeline and drops the prior before anything is trained.** The prior pipeline (prior model + CLIP ViT-G text and image encoders) takes ~7 GB in float16 and is released before training so the UNet training graph has full VRAM headroom. Section 5 encodes the 60 captions, the generation prompts and the empty negative prompt, caches the image embeddings, and releases the prior; the fresh pipeline of Section 9 adopts the same cached embeddings instead of loading the prior again.

**It scores a generator without pretending a number is quality.** Generation has no ground truth, so the notebook reads three kinds of number and names each: the held-out *denoising loss* (the training objective on photographs the model never trained on, with identical noise for the frozen and the adapted model; the only assertion is the guaranteed one, that the kept epoch's validation loss is no higher than the frozen model's, and the test loss is printed, not asserted), CLIP scores of generated images (prompt alignment, which species CLIP thinks it sees, closeness to the held-out photographs), and the same CLIP scores on the real photographs — the *real-photo ceiling*. None of them is a human judgement.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules (`pipeline.py`, `samples.py`, `metrics.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrite makes the weights root working-directory-relative and removes internal relative package imports), Section 3 carries the three snapshot manifests inline and asserts each against the module's constants before staging, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifests, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files`, `stage_missing_prior_files` and `stage_missing_scorer_files` fetch only the manifest entries that are absent, from the Hugging Face Hub at the immutable revisions (never `main`); `verify_snapshot`, `verify_prior_snapshot` and `verify_scorer_snapshot` re-hash every entry; `KandinskyPipeline.from_pretrained(weights_dir=..., prior_dir=..., use_lora=True)` loads the decoder UNet with an untrained LoRA attached, the MoVQ, and the scheduler config; the prior is loaded by `encode_prompts` and released by `release_prior`. Every file is safetensors or JSON/text; nothing is unpickled and no remote code runs.
- **Stages (§4.1):** `fetch_sample_dataset` / `load_byod_dataset` (sample acquisition) → `dataset_manifest` + `validate_dataset` refusal probes (validation, with the ceilings and a dataset digest) → seeded stratified roles (36 / 12 / 12) → `pipe.encode_prompts` + `release_prior` → `pipe.evaluate` and `pipe.generate` + `score_generations` on the frozen model with `real_photo_baseline` (baseline) → `pipe.adapt` (bounded LoRA fine-tuning) → `pipe.evaluate` / `pipe.generate` again on identical inputs (evaluation) → `pipe.generate` on a new prompt (inference) → `pipe.save_artifact` → `KandinskyPipeline.from_artifact` + `import_prompt_cache` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** CLIP cosine similarities and the argmax label rule are labelled as what they are; the denoising loss is the training objective, not a quality measure; no threshold is set and no calibration is claimed.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the frozen model is scored before adaptation on the same seeded latents, noise and timesteps, and the real-photo ceiling is scored on the same photographs; every metric is labelled sample-sanity evidence from 12 held-out photographs and 12 generated images with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** the split is seeded and stratified per species, no image appears in two splits (`check_split_disjoint`), validation selects the epoch and the test records are used for nothing but the final comparison; the notebook states that the captions are one template per species and that photographs of the same individual or observer should be grouped in real data. In BYOD mode the split is by caption.
- **Ceilings (VAL6):** the image-size range, the caption length, the token truncation and the record range are stated in the Prerequisites and printed from the schema before the model runs; three refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user records flow through the same validation, encoding, baseline, adaptation, evaluation, generation, export and reload cells. The expected zip layout, the image and caption contract and the privacy guidance — photographs of identifiable people and licensed material are restricted data — are stated in the Prerequisites and in Section 4, and a captions CSV is written to `outputs/` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
